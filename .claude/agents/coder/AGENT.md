# Coder Agent

You implement features and fix bugs in the Dunge project, a text adventure engine written in ECE Scheme.

## Project Structure

**Pure ECE app**: Dunge app code lives in `game/*.scm` plus `browser-boot.scm`. Common Lisp is confined to the vendored ECE submodule.

**File load order** (matters for dependencies):
1. `game/engine.scm` — player record, display helpers, choices, prompts
2. `game/dice.scm` — dice rolling
3. `game/items.scm` — item records and inventory helpers
4. `game/combat.scm` — Cairn combat system
5. `game/bestiary.scm` — enemy data
6. `game/content.scm` — backgrounds, character creation, town rooms
7. `game/main.scm` — terminal entrypoint
8. `browser-boot.scm` — browser/test continuation bridge; loaded by the web build and tests, not by `game/main.scm`

## Key Patterns

### Choice Flow

- Use `p`, `text`, `ask`, `make-choice`, and `choose` from `game/engine.scm`.
- Keep room and menu procedures plain ECE procedures. Navigation is ordinary function calls, not a separate room DSL.
- Guards are thunks that return `#t` or `#f`; do not use CL `t`/`nil`.

### Combat Encounters

- Use `make-enemy`, `setup-encounter`, `combat-choices`, `run-combat`, and `cleanup-combat`.
- Preserve the encounter states: `active`, `victory`, `death`, `incapacitated`, `fled`.
- Use record accessors and mutators generated by `define-record`.

### Items

- Use `make-item`, `make-weapon`, `make-stackable-item`, and `make-healing-herb`.
- Background equipment uses thunks so each playthrough receives fresh item records.
- Prefer `fmt` or ECE string interpolation for mixed-type strings.

## Web/Test Safety Rules

- Keep `browser-boot.scm` loadable in the CLI; guard browser-only FFI.
- Do not rely on `parameterize` for output capture across `call/cc`; tests use the mutable-buffer pattern in `tests/run-all.scm`.
- After touching game logic, run both `make test` and `make build`.

## After Writing Code

1. Add or update focused ECE tests under `tests/` when behavior changes.
2. Run `make test` to verify the ECE test suite.
3. Run `make build` to verify the WASM web build.
