[[https://anthonyf.github.io/dunge-cl/][Play in your browser]]

** Overview

Dunge is a solo RPG text adventure using [[https://cairnrpg.com/cairn-srd/][Cairn]] mechanics — three stats (STR/DEX/WIL), automatic damage with armor reduction, and critical damage via HP→STR spillover. Players create a character, choose a background, and explore a choice-based world with combat encounters.

Game content is written in [[https://github.com/anthonyf/ece][ECE]], a Scheme dialect with first-class continuations, macros, and string interpolation. ECE targets two deployment modes from the same game code:
- *Terminal* — the ECE interpreter runs the game as a synchronous REPL
- *Browser* — ECE's app tooling compiles the game to a WASM bundle for event-driven DOM rendering, and ~ece-serve~ provides a live browser development server

** Quick Start

#+begin_src bash
# Clone with submodules (ECE is vendored at vendor/ece/)
git clone --recurse-submodules https://github.com/anthonyf/dunge-cl.git
cd dunge-cl

# First time: build the vendored ECE toolchain and browser dev assets
make ece

# Everyday commands
make run       # Terminal game
make test      # Run all tests
make build     # Web build (produces dist/)
make serve     # Live browser dev server on http://127.0.0.1:8080
make clean     # Remove dist/
#+end_src

If you forgot ~--recurse-submodules~, run ~git submodule update --init~ to populate ~vendor/ece/~.

~make run~, ~make test~, ~make build~, and ~make serve~ all depend on the in-tree ECE binary and will trigger the ECE build automatically on first use. ~make ece~ also refreshes the ignored runtime files under ~web/~ so Emacs jack-in sessions can start the browser app directly.

** Browser App Development

ECE creates new browser apps with:

#+begin_src bash
vendor/ece/bin/ece init web my-app
#+end_src

Dunge already has that app-local browser surface under ~web/~:
- ~web/main.scm~ is the ~ece-serve~ entrypoint. It loads the game files and ~browser-boot.scm~.
- ~web/index.html~ is the custom Dunge host page and works both in standalone ~dist/~ builds and in live ~ece-serve~ sessions.
- ~make ece~ and ~make web-dev-assets~ copy the ignored ECE runtime assets needed by ~ece-serve~ into ~web/~.
- ~web/.dir-locals.el~ points Geiser at the vendored ~../vendor/ece/bin/ece-repl~ so jack-in does not accidentally use an older globally installed ~ece-serve~.

The Emacs jack-in flow uses ~web/main.scm~ as the current buffer because ~geiser-ece-dev-jack-in~ treats the current ~.scm~ file as the app entrypoint and ~ece-serve~ serves ~index.html~ from that file's directory.

#+begin_src text
M-x load-file RET vendor/ece/emacs/geiser-ece.el RET
C-x C-f web/main.scm
M-x geiser-ece-dev-mode
M-x geiser-ece-dev-jack-in
#+end_src

That starts ~ece-serve~, opens ~http://127.0.0.1:8080/~, and opens an ~ece-dev>~ REPL connected to the browser runtime. After jack-in, edit files under ~game/~ or ~browser-boot.scm~ and use the ~geiser-ece-dev-*~ eval/reload commands; saving a watched file also triggers an app rebuild and browser reload.

If Emacs already had ~web/main.scm~ open before ~web/.dir-locals.el~ existed, run ~M-x normal-mode~ in that buffer (or reopen the file) and accept the directory-local variables before jack-in. A page showing only ~Not Found: /~ usually means Emacs started an older/global ~ece-serve~ instead of the vendored one.

You can still start the same dev server from the terminal with:

#+begin_src bash
make serve PORT=8080
#+end_src

Then open ~http://127.0.0.1:8080/~ or attach from Emacs with ~geiser-ece-dev-connect-repl~. ~ece-serve~ writes local session metadata and a dev token so Emacs can attach without pasting a token manually.

** Dependencies

- [[https://github.com/anthonyf/ece][ECE]] — vendored as a git submodule at ~vendor/ece/~, pinned to a specific commit
- [[https://www.sbcl.org/][SBCL]] — Common Lisp compiler (build-time only, used to build ECE)
- [[https://github.com/fukamachi/qlot][Qlot]] — CL dependency manager (build-time only, used to build ECE)
- [[https://github.com/WebAssembly/binaryen][binaryen]] — ~wasm-as~ for the web target (version 129+ for WASM GC support)
- [[https://www.gnu.org/software/make/][GNU Make]] — build automation
- [[https://nodejs.org/][Node.js]] + [[https://playwright.dev/][Playwright]] — browser tests (~npm install~)

SBCL, Qlot, and binaryen are only needed when (re)building the vendored ECE submodule. Dunge delegates that build with plain ~make -C vendor/ece~; ECE's own Makefile handles any internal setup and creates ~vendor/ece/bin/ece~ plus its dispatcher symlinks. Once ~vendor/ece/bin/ece~ exists, Dunge's everyday commands don't invoke those build tools directly.

** Bumping the ECE pin

ECE is vendored as a submodule, so updating it is a reviewable commit:

#+begin_src bash
cd vendor/ece
git fetch origin
git checkout <new-sha>
cd ../..
make ece          # rebuild the submodule
make test         # verify
make build        # verify browser packaging
make serve        # optional live browser smoke check
git add vendor/ece
git commit -m "Bump ECE to <new-sha>"
#+end_src
